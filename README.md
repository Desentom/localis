# Localis

Офлайн-нейросеть на телефоне. Работает без интернета, всё считает сам
телефон, ничего никуда не отправляет.

Flutter + llama.cpp. Android.

---

## Что это и что это не

**Это.** Локальный ассистент для быстрых задач: объяснить тему, разобрать
уравнение, написать черновик текста, перевести фразу, подсказать план.
Работает в метро, самолёте, в деревне. Ничего не уходит наружу.

**Это не.** Не ChatGPT. Модель, которая помещается в память телефона, — это
0.6–4 миллиарда параметров против сотен миллиардов у облачных. Она не знает
новостей, не откроет сайт, иногда уверенно выдумывает факты. Об этом написано
прямо в интерфейсе — см. «Почему так честно» ниже.

---

## Почему так честно

Самая частая причина плохих отзывов у локальных ИИ-приложений — не баги, а
разрыв между ожиданием и реальностью. Человек ставит «ИИ-ассистент», пробует
написать эссе, получает две ошибки из пяти предложений и ставит одну звезду.

Поэтому в приложении:

- **перед скачиванием** показаны честные цифры: размер, скорость
  «5–9 ток/с» для среднего телефона и описание того, что модель
  **не** умеет;
- **модель не одна** — четыре размера, человек выбирает под свой телефон;
- **нехватка памяти не означает отказ** — вместо блокировки приложение
  ужимает контекст диалога до того, что телефон потянет, и честно пишет
  об этом в настройках; заблокирована бывает только та модель, которая
  не запустится физически, и даже самая лёгкая остаётся доступной всегда;
- **рядом с каждым ответом** показывается скорость генерации — видно, что
  это локальный движок, а не облако;
- **приложение бесплатное по-настоящему**: себестоимость ответа равна нулю,
  потому что токены считает телефон. Платные подписки на этом фоне
  выглядели бы нечестно.

## Где всё лежит

Проект и всё окружение для сборки — на диске **W:**.

```
W:\localis                 ← проект
W:\dev\flutter             ← Flutter SDK
W:\dev\jdk-17              ← JDK 17
W:\dev\android-sdk         ← Android SDK + NDK
W:\dev\_downloads          ← архивы установщика
```

Так сделано намеренно: на диске C: свободно около 6 ГБ, а Flutter с Android
SDK занимает 8–9 ГБ. Заодто уходит проблема OneDrive — он держит файлы
захваченными, и Gradle падает с ошибкой про блокировку файла.

## Требования

| | |
|---|---|
| Flutter | 3.24 или новее (нужен Dart 3.3+) |
| Android SDK | API 35 |
| JDK | 17 |
| NDK | **r27 или новее** — обязателен из-за требования Google Play к страницам памяти 16 КБ |
| Устройство | Android 8.0 (API 26) и выше |

Android Studio **не требуется** — для сборки APK хватает командной строки.
Экономит 1,5 ГБ, которые на диске W: пригодятся под SDK.

> **NDK r27 — не формальность.** С ноября 2025 Google Play не принимает
> приложения, собранные старыми NDK: Android 15 использует страницы памяти
> 16 КБ, и старые бинарные библиотеки в них не работают.

Самому собирать llama.cpp **не нужно**: плагин `llama_flutter_android`
привозит готовые `.so` для архитектур телефонов.

## Установка окружения

```powershell
powershell -ExecutionPolicy Bypass -File W:\dev\_downloads\get.ps1
powershell -ExecutionPolicy Bypass -File W:\localis\tool\setup_env.ps1
```

Первый скрипт скачивает JDK, Flutter и Android command line tools.
Второй распаковывает их, принимает лицензии SDK, ставит
`platform-tools`, `platforms;android-35`, `build-tools;35.0.0` и NDK 27,
после чего прописывает `JAVA_HOME`, `ANDROID_HOME` и `PATH` для вашего
пользователя.

Оба скрипта идемпотентны — их безопасно запускать повторно после обрыва.

После установки **перезапустите терминал** и проверьте:

```powershell
flutter doctor -v
```

> Если PowerShell ругается на кириллицу в `.ps1` — это Windows PowerShell 5.1
> читает файлы без BOM как ANSI. Оба скрипта уже сохранены с BOM; если
> правите их вручную, сохраняйте именно так.

## Сборка

### 1. Создать оболочку Flutter

Gradle-обвязку (`gradlew`, `gradle-wrapper.jar`) генерирует только Flutter,
поэтому сначала создаём проект, потом кладём наши файлы.

```powershell
cd W:\localis_tmp
flutter create --platforms=android --org ru.localis --project-name localis localis_gen
```

Скопируйте содержимое `localis_gen` (кроме `lib\main.dart` и `test\`) в
`W:\localis`, затем удалите временную папку. Либо, если файлы проекта уже
лежат на месте, скопируйте из сгенерированного каталога только недостающее:
`android\gradlew`, `android\gradlew.bat`, `android\gradle\` и
`android\app\src\main\res\mipmap-*`.

`flutter create` перезапишет `lib/main.dart` — после этого верните наш
файл из репозитория.

### 2. Вернуть файлы проекта

Скопируйте поверх созданного каталога:

```
pubspec.yaml
analysis_options.yaml
.gitignore
lib/                       ← полностью
android/app/build.gradle.kts
android/app/proguard-rules.pro
android/app/src/main/AndroidManifest.xml
android/app/src/main/kotlin/ru/localis/ai/MainActivity.kt
android/app/src/main/res/values/{styles,colors,strings}.xml
android/app/src/main/res/drawable/launch_background.xml
android/build.gradle.kts
android/settings.gradle.kts
android/gradle.properties
tool/
test/
```

### 3. Зависимости, проверка и запуск

```powershell
cd W:\localis
flutter pub get
flutter analyze
flutter test
flutter run
```

Приложение запустится **без Firebase и без интернета** — работает гостевой
режим. Google-вход подключается отдельным шагом.

### 4. Проверить каталог моделей

```powershell
powershell -ExecutionPolicy Bypass -File tool\verify_models.ps1
```

Скрипт делает HEAD-запросы и сверяет размеры файлов с тем, что записано в
коде. Ссылка, которая протухла, ломает приложение у пользователя ровно на
экране загрузки — раньше это проверить нечем.

Получить контрольные суммы (около 6 ГБ трафика):

```powershell
powershell -ExecutionPolicy Bypass -File tool\verify_models.ps1 -Download
```

Скопируйте выведенные строки `sha256: '...'` в соответствующие `ModelSpec` в
`lib/data/model_spec.dart`. После этого загрузка проверяется и битый файл
удаляется вместо того, чтобы ломать движок.

### 5. Тесты

```powershell
flutter test
flutter analyze
```

## Google-вход

Вход **не обязателен**. Приложение полностью работоспособно без аккаунта —
все вычисления локальные, а логин без сервера не даёт ничего. Принудительный
вход перед первым вопросом отсекает значительную часть установок, а офлайн
всё равно не позволяет им пользоваться.

Когда появится облачная синхронизация истории — вход станет осмысленным.

Подключение:

1. <https://console.firebase.google.com> → новый проект.
2. **Build → Authentication → Sign-in method** → включить **Google**.
3. **Project settings → Your apps → Android** → добавить приложение с
   package name `ru.localis.ai` → скачать `google-services.json` в
   `android/app/`.
4. Раскомментировать плагин в `android/settings.gradle.kts` и
   `android/app/build.gradle.kts`:
   ```kotlin
   id("com.google.gms.google-services") version "4.4.2" apply false   // settings
   id("com.google.gms.google-services")                                  // app
   ```
5. Взять **Web client ID** и **Server client ID** из `google-services.json`
   и передать при сборке:
   ```powershell
   flutter run `
     --dart-define=GOOGLE_WEB_CLIENT_ID=123.apps.googleusercontent.com `
     --dart-define=GOOGLE_SERVER_CLIENT_ID=123.apps.googleusercontent.com
   ```
6. В `lib/main.dart` раскомментировать блок внутри `FirebaseBootstrap.run()`
   и создать `lib/firebase_options.dart` через FlutterFire CLI:
   ```powershell
   dart pub global activate flutterfire_cli
   flutterfire configure
   ```

Крипто-подпись для release — см. следующий раздел.

## Выпуск в Google Play

```powershell
keytool -genkey -v -keystore ~/upload-keystore.jks -keyalg RSA `
        -keysize 2048 -validity 10000 -alias upload
```

`android/key.properties` (в репозиторий **не** попадает):

```properties

keyPassword=...
keyAlias=upload
storeFile=/путь/к/upload-keystore.jks
```

В `android/app/build.gradle.kts` заменить `signingConfigs.getByName("debug")`
на блок с `signingConfigs { create("release") { ... } }`.

Сборка:

```powershell

```

### Обязательные пункты анкеты

| | |
|---|---|
| **Формат** | AAB. Лимит 200 МБ на установку; модель в него не входит — она качается после установки, поэтому APK остаётся лёгким |
| **Минимальная версия** | API 26 (Android 8.0) |
| **Data Safety** | Заполнить честно: при включённом Google-входе Firebase получает имя и почту. «Данные не собираются» здесь будет ложью, и Play это проверяет |
| **Политика конфиденциальности** | Обязательна ссылка на работающую страницу |
| **Возрастной рейтинг** | Заполнить анкету; рекламы нет — это упрощает ответы |
| **16 КБ страницы памяти** | Проверить готовым инструментом Google до отправки |

### Отдельный риск: школьники и Families Policy

Вы сказали, что приложение нужно школьникам. Здесь есть юридическая развилка,
которую нужно решить **до** релиза.

Google Play запрещает Google-вход и Google Play Services в приложениях, которые
напрямую адресованы детям младше 13 лет, и требует соответствия правилам
Families Program. Нарушение — не предупреждение, а удаление приложения.

- **Аудитория 14+ (старшеклассники, студенты, взрослые)** — Families Policy
  не применяется, всё как описано выше.
- **Есть младшие школьники** — нельзя использовать Google-вход, нужен свой
  возрастной экран и подтверждение родителя.

Разумный путь: позиционировать приложение для подростков и взрослых, в описании
не писать «для детей 6 лет». «Школьники» в русском контексте обычно означает
14–17 лет, и это снимает проблему.

## Архитектура

```
lib/
├── main.dart                  инициализация, запуск
├── app.dart                   выбор экрана по стадии
├── core/
│   ├── theme.dart             цвета, градиенты, тема Material 3
│   └── format.dart            байты, скорость, склонения
├── data/
│   ├── model_spec.dart        каталог моделей: URL, размеры, ожидания
│   ├── chat_message.dart      сообщения и диалоги
│   ├── chat_store.dart        история в JSON, атомарная запись
│   ├── settings_store.dart    настройки
│   ├── personas.dart          пресеты поведения
│   └── device_capability.dart память, ядра, поддержка Vulkan
├── services/
│   ├── engine_service.dart    ВСЕ вызовы llama.cpp в одном файле
│   ├── model_downloader.dart  скачивание с докачкой и проверкой
│   ├── auth_service.dart      Google-вход, гостевой режим
│   └── device_capability.dart (в data/)
├── state/
│   └── app_controller.dart    единое состояние, ChangeNotifier
└── ui/
    ├── screens/               splash, model_setup, chat, history, settings
    └── widgets/               фон, пузыри, кнопки, пилюли
```

Два решения, которые стоит знать до того, как что-то менять:

**Все вызовы llama.cpp собраны в `engine_service.dart`.** Плагин обновляется
чаще, чем меняется API llama.cpp. Когда прилетит обновление и сигнатуры
поедут, правится один файл, а не весь проект.

**Фон рисуется мягкими радиальными градиентами, а не `BackdropFilter` на весь
экран.** На среднем телефоне настоящее размытие съедает 15–25 кадров в
секунду. Здесь то же самое выглядит так же и стоит ноль производительности.

## Производительность: чего ожидать

Реальные цифры для моделей из каталога, телефон среднего класса
(Snapdragon 6-серии, 6–8 ГБ ОЗУ):

| Модель | Размер | Скорость | Нужно свободной RAM |
|---|---|---|---|
| Qwen3 0.6B | 396,7 МБ | 20–35 ток/с | 0,9 ГБ |
| Qwen3 1.7B | 1,11 ГБ | 8–18 ток/с | 1,9 ГБ |
| Qwen2.5 3B | 2,1 ГБ | 4–9 ток/с | 3,4 ГБ |
| Qwen3 4B | 2,5 ГБ | 2–6 ток/с | 3,9 ГБ |

Цифры в последней колонке — это **не** размер файла и не удвоенный размер
файла. llama.cpp открывает веса через `mmap`: они не копируются в память,
а подгружаются страницами по мере надобности, и ядро может вытеснить
неиспользуемые обратно в хранилище. Формула в коде —
`размер файла × 1,45 + 300 МБ` (`ModelCatalog._weightFactor`).

При нехватке памяти приложение не отказывает: контекст диалога
уменьшается автоматически, об этом написано в настройках.

На флагманах скорость выше в 2–3 раза. На устройствах с Vulkan часть слоёв
уходит на GPU — плагин определяет это сам.

Для 3B и 4B **контекст 4096 — предел**: модель начинает терять нить диалога
раньше, чем показывает счётчик.

## Как растить аудиторию

- **Скринкаст реальной скорости.** Главный аргумент — «смотри, 15 ток/с
  прямо на телефоне, без сети». Это то, что не могут показать облачные
  конкуренты, и это снимает половину вопросов в комментариях.
- **Формат «школьная задача → ответ».** Короткие вертикальные видео с
  разбором одного примера. Целевая аудитория сама ищет решение — вопрос
  «а покажи на примере» продаёт приложение лучше любого описания.
- **Раздел про офлайн.** «Работает в метро и самолёте» — то, что понимает
  любая аудитория без объяснений.
- **Обратная связь внутри приложения.** Люди жалуются в отзывах, а не в
  поддержку. Просите оценку после первых трёх удачных ответов.

И не обещать того, чего модель не умеет. Лучше скромная оценка от реального
пользователя, чем громкая от разочарованного.

## Переименование

Рабочее название — заглушка. Сменить нужно пять мест:

1. `pubspec.yaml` → `name:`
2. `android/app/build.gradle.kts` → `namespace` и `applicationId`
3. `android/app/src/main/kotlin/ru/localis/ai/MainActivity.kt` — путь и
   первую строку `package ru.localis.ai`
4. `android/app/src/main/AndroidManifest.xml` → `android:name=".MainActivity"`
5. `android/app/src/main/res/values/strings.xml` → `app_name`

Плюс `lib/core/theme.dart` → `AppColors`, если нужен свой фирменный цвет.
